# 火星全境｜Three.js 可交互网页

一颗改造后的未来火星，可以从整球连续推近到地形、城区、街区和任意一栋建筑（四面、屋顶、入口、室内），再回到轨道上的同一经纬度。

- 地形先行，城市从地形里长出来。
- 12 个省域按 `参考图/03-control` 的控制图生成：富氧改造区 OX1–OX6，宜居城市祝融市 ZR1–ZR6。
- 两处巨构：G01 东海分段潮堤、G02 南台地水阶。
- 有昼夜、分级夜光、云和大气，并提供 §5 九张镜头卡的书签。
- 世界种子 `351165`，世界版本 `mars-world-1.0.0`。同一 ID 在任何会话里都得到同一栋楼。

艺术设定见 [`prompt.md`](prompt.md)，模块契约见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。

## 快速开始

需要 Node.js ≥ 20.19 和支持 WebGL2 的浏览器（推荐桌面版 Chrome / Edge / Safari 17+，独立显卡或 Apple Silicon）。

```bash
cd web
npm ci                 # 安装依赖（版本已锁定）
npm run prep:data      # 由 data-src/03-control 的控制图重新生成 public/data/*.bin（生成结果已提交，可跳过）
npm run dev            # 开发服务器 http://127.0.0.1:5173
```

生产构建与预览（只打包网页本身，不含 dev/ 测试台）：

```bash
npm run build          # 输出到 dist/
npm run preview        # http://127.0.0.1:4173
```

首次打开会先显示整球，地形、城市和建筑按视距逐级加载。远处是粗级，越近越细，最终画质不打折扣。
本项目没有性能预算，按最佳画质渲染。机器越强，细化越快。

## URL 参数

| 参数 | 说明 |
|---|---|
| `pose=lat,lon,alt,heading,pitch[,lens]` | 相机位置：纬度、经度、离地高度 m、方位°、俯仰°、焦距 mm（全画幅等效） |
| `time=<h>` | 火星时（经度 0° 处的太阳时）。当地太阳时 = time + 经度 / 15 |
| `bookmark=<ID>` | 打开书签 |
| `select=<建筑ID>` | 选中并聚焦一栋建筑 |
| `mode=orbit\|fly\|walk` | 初始模式 |
| `clean=1` | 纯净画面（无界面、标签、描边、调试） |
| `debug=<图层>` | 调试图层（也可在「图层」面板切换）：<br>• `objectId` 建筑稳定 ID 色<br>• `wireframe` 地形网格与 LOD 接缝<br>• `lod` 细节层级<br>• `province` 十二省域<br>• `zone` 富氧区 / 宜居区<br>• `density` 建设密度控制图<br>• `emission` 夜光控制图<br>• `normals` 法线 |
| `workers=<n>` | 地形与世界生成 Worker 数量：默认为核心数 − 2，最多 4 个。同一页面的所有 JS 堆在一个渲染进程里，Worker 太多会在最密城区导致内存溢出崩溃 |
| `detailMB=<n>` | 精细建筑的显存预算（MB，默认 2600）。显存或统一内存较小的机器可以调低，预算外的远处建筑改用远景立面 |

## 建筑 ID

每栋建筑都有稳定的字符串 ID，以省域代码开头，例如 `ZR1-0.3.1a5.17w-n8.n6-7`。ID 由地块、实例序号和世界种子派生，不依赖全局状态：

- 任何会话里，用同一 ID 都能重新生成同一栋楼，包括用途、朝向、占地、层数、入口、层表和邻接关系。
- 每栋楼有三级资产：
  - `mass`：远景体量；
  - `exterior`：完整外观；
  - `full`：外观、室内与步行碰撞体。

在搜索面板（`/`）输入 ID 即可飞到该楼。选中后的建筑面板列出用途、省域、地块、坐标、层数、入口，并提供人眼机位按钮。

## 自动化与截图

页面暴露 `window.__MARS__`：

| 成员 | 作用 |
|---|---|
| `goto(书签ID或位姿)` | 返回 Promise |
| `waitIdle(ms, 帧数, {throttle})` | 等到所有瓦片和建筑都加载到最终画质（连续若干帧空闲才算）。`throttle: N` 时等待期间每 N 帧才渲染一帧，流式加载照常进行，CPU 让给生成 Worker；加载完成后恢复逐帧渲染 |
| `capture({scale})` | 导出高分辨率定格 |
| `setTime(h)` | 设置时刻 |
| `pose()` | 读取当前位姿 |
| `stats()` | 读取统计信息：帧率、绘制调用、各 Worker 池按任务类型的次数 / 平均耗时 / 排队时间 / 回传延迟、地形瓦片按纹理分辨率的构建耗时、各子系统是否空闲 |
| `bookmarks()` | 列出书签 |

```bash
# 单张截图（系统 Chrome 无头模式，使用真实 GPU）
node scripts/shot.mjs --base http://127.0.0.1:4173 --url "/?bookmark=S05&clean=1" --out shots/s05.png --width 1920 --height 1080
# 按书签批量出图（每个书签一个冷启动页面；每张最多等 300 秒，等待期间降帧）
node scripts/capture-shots.mjs --base http://127.0.0.1:4173 --out shots/final --width 1920 --height 1080 --query "&workers=4" --idle 300000 --throttle 8
# 批次中断后续拍：只拍 report.json 里还没有成功定格的书签，结果并入同一份报告
node scripts/capture-shots.mjs --base http://127.0.0.1:4173 --out shots/final --width 1920 --height 1080 --query "&workers=4" --idle 300000 --throttle 8 --missing
# 加载收敛诊断：单个书签每 30 秒采样一次各类任务的进度和耗时
node scripts/diag-converge.mjs --base http://127.0.0.1:4173 --bm S03 --secs 420 --sample 30 --throttle 8
# 开拍前自检：Node、本机依赖、构建、Chrome，以及 WebGL 实际用到的显卡
node scripts/check-env.mjs
# 收敛补拍（macOS / Windows 通用）：自带预览服务，按分组文件逐组拍到完全收敛，已收敛的自动跳过，第二轮补失败的组
node scripts/converge-batch.mjs --serve --groups scripts/converge-remaining.json --passes 2
# 只列出会拍哪些书签，不开浏览器
node scripts/converge-batch.mjs --groups scripts/converge-remaining.json --dry-run
```

拍摄脚本按系统自动选 Chrome 路径和图形后端（macOS 用 Metal，Windows 用 D3D11，见 `scripts/chrome.mjs`）。在核显 + 独显的 Windows 笔记本上补拍，加 `--gpu NVIDIA`，确保不会落到核显或软件渲染上；完整步骤见 [`notes/windows-capture.md`](notes/windows-capture.md)。

### 抽查要点

- **全盘识读：** S01 用春分构图，晨曦线竖直穿过城团。东内海周围是日侧的 ZR1、ZR4、ZR5 东翼，夜侧是 ZR5 核心与 ZR1 西翼。S02 是东内海夜半球：三个城网围着大块暗水，城与城之间有长暗隙。
- **旋转与换时：** 转台书签 `TE0`/`TE90`/`TE180`/`TW90` 锁定同一曝光。云场只由时刻决定，切换时刻后可复原。
- **长会话稳定性：** `scripts/memory-soak.mjs` 用单页面在 4 个地点之间跨尺度循环 26 分钟，页面不崩溃，纹理数、几何数、JS 堆和进程占用都不再单调增长。

### 已知限制

- G01 东海分段潮堤长约 11 km，在 S01 全盘下约 1 个像素。轨道尺度用不低于 1.6 像素的堤顶亮线和港池静水色表现，2000 km 内可清楚读出弧形。
- 最高画质在街面视角的 GPU 占用约 5–7 GB，适合 16 GB 以上内存、Apple Silicon 或独立显卡的机器。8 GB 显存的独显可以跑，峡谷全景 S06 这类最大的视角接近上限。
